**Goal:** закрыть все замечания ревью доступности кита от 2026-11-16.

**Architecture:** правки внутри существующих компонентов, без новых runtime-зависимостей. Четыре PR в `main`,
каждый со своей веткой от свежего `main`: (A) только атрибуты и имена, (B) поведение и разметка,
(C) визуальное — после согласования с дизайном, (D) автоматический axe — после согласования с командой.

**Tech Stack:** React 19, `@base-ui/react` 1.9.0, react-i18next (namespace `ui-kit`), vitest + happy-dom +
Testing Library, Storybook 10.6.5 с `@storybook/addon-a11y`.

**Spec:** ревью в разговоре от 2026-11-16 (пункты 1–15 и «мелкие»). Номер пункта указан у каждой задачи как `[R n]`.

## Global Constraints

- Новые строки — ключи в `i18n/locales/*.json`, **во всех 10 локалях** (de en es fr id it pl pt ru tr), namespace `ui-kit`.
- Никаких hex/rgba в модулях — только `var(--color-*)`; никаких element-селекторов и `:global`.
- Компонент с хуками/base-ui начинается с `'use client'`. Импорты внутри кита — относительные.
- Пути файлов — публичный API: ничего не переименовывать и не переносить.
- A11y-правка добавляет атрибуты; вид и поведение меняются только в задачах, помеченных **[design]** / **[behaviour]**.
- Тесты компонентов — `*.dom.test.tsx` рядом с компонентом, первая строка `// @vitest-environment happy-dom`;
  happy-dom открывается на 1024px; после `el.focus()` шли `fireEvent.focus(el)`.
- i18n в тестах не инициализирован: `t()` возвращает ключ — ассертить по ключу.
- Каждая задача заканчивается зелёными: `npm run typecheck && npm run lint && npm test`.
  Перед PR дополнительно `npm run build-storybook`, и у затронутых стори 0 нарушений в панели Accessibility.
- Не пушить без явного «ок» пользователя. Коммит — Conventional Commits, `fix(<Component>): …`.
- Visually-hidden текст — класс `.srOnly` в модуле компонента, копия из `ScheduleGrid/ScheduleGrid.module.scss:70`
  (общего миксина нет; не выносить в `styles/` в рамках этого плана).

## Решения, которые нужно подтвердить до PR C

| Что | Предложение (применяется, если не скажут иначе) |
| --- | --- |
| Кольцо фокуса у Tabs, TabsRounded, кнопок Combobox | как у `Tag`: `outline: 2px solid var(--color-blue-300); outline-offset: 2px` на `:focus-visible` |
| Фокус у Input/Textarea/TagsInput/CodeField | то же кольцо на `.controlWrapper:has(:focus-visible)`, в том числе в состоянии ошибки; у CodeField — на `.box:focus-visible` |
| Длительность тостов | обычный/success — 4000 мс, error/warning — 7000 мс, loading — без изменений |
| ButtonWithTooltip на десктопе | заменить `Tooltip` на `Popover` с теми же стилями карточки; фокус уходит в карточку при открытии и возвращается на кнопку |
| Skeleton при `prefers-reduced-motion: reduce` | `animation: none` |
| `blur()` у `Button`/`IconButton` на `pointerUp`/`touchEnd` | оставить (убирает «залипшее» кольцо после клика); возврат фокуса решает `finalFocus` (Task 8b). Пересмотреть, если Step 0 задачи 8b покажет потерю фокуса у VoiceOver |
| Начальный фокус в ConfirmDialog | оставить base-ui по умолчанию — крестик (безопасное действие, не «Удалить») |
| D: автоматический axe | devDeps `@storybook/addon-vitest@10.6.5`, vitest browser mode с `@vitest/browser-playwright`, скрипт `test:stories` |

## Review Focus

1. **Повторное открытие оверлея после закрытия** (ButtonWithTooltip, мобильный Combobox): фокус на триггере, Enter снова открывает. Тесты в задачах 11 и 20.
2. **TagsInput: лимит `maxTags` достигнут, потом тег удалён**: фокус ни разу не падает на `<body>`. Тест в задаче 10.
3. **Modal без `title`, но с `aria-label`**: имя диалога из `aria-label`, пустого заголовка в DOM нет; у ConfirmDialog описание — его текст, а не всё окно. Тест в задаче 8.
6. **Модалка открыта кликом или тапом по кит-`Button`**: после закрытия фокус на кнопке, а не в начале страницы. Тест в задаче 8b.
4. **IconButton `loading` при нажатии с клавиатуры**: Enter не вызывает `onClick`, фокус остаётся на кнопке. Тест в задаче 12.
5. **DatePicker после смены месяца стрелками**: имя дня по-прежнему с днём недели; `role="combobox"` не ломает открытие по Enter/↓. Тест в задаче 6.
